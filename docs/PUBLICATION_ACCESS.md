# Publication access and what it means

Authority class: current summary. Recorded under DEC-022. This document changes no hosting setting.

## Current truth

| Question | Answer |
|---|---|
| Is the Lovable project private? | Yes. |
| Is the published application URL reachable by anyone with the link? | Yes. |
| Is the published surface access-controlled? | No. The private project setting does not restrict it. |
| Does the robots file prevent access? | No. `public/robots.txt` is a crawler request, not access control. |
| Is anything on the surface real? | No. Every record shown is synthetic. There is no personal data, no authentication, no database, and no production data path. |
| Is the application released? | No. Hosting is not release authority. |

The interface must therefore describe itself as a **public synthetic prototype, no real personal
data, not released**. Any statement that the published surface is a private workspace is false and
has been removed.

## Manual owner actions

Neither action is performed automatically, and neither is performed by this repository.

1. **Make the deployment private.** In the Lovable project, open Project Settings → Publish
   visibility and set it to private. The published URL then requires workspace membership.
2. **Unpublish the deployment.** In the Lovable project, open Project Settings and use Unpublish.
   The published URL becomes unreachable.

Until one of those actions is taken by the owner, the surface stays publicly reachable and the
boundary language above is the accurate description of it.

## Non-claims

Nothing here asserts that the published surface is secure, reviewed, accessible, conformant, or fit
for district use. It states reachability and nothing else.
